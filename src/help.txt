devsrv - start, wait for, inspect and stop dev servers, for coding agents

Usage:
  devsrv start NAME [--port auto|N] [--ready http[:PATH]|port|log:REGEX|none]
               [--timeout 30s] -- CMD ARGS...
  devsrv ls [--all]                  what devsrv started here: name, state, pid, port, age
  devsrv logs NAME [-n 50] [--follow-until REGEX [--timeout 30s]]
  devsrv stop NAME... | --all        stops only the process groups devsrv started
  devsrv who PORT                    who listens on PORT (never stops it)
  devsrv wait [--timeout 30s] [--interval 0.5s] URL [--status 200] | port N
              | file PATH [REGEX] | log NAME REGEX | gone PID | cmd -- CMD ARGS...

Examples:
  devsrv start web --port auto -- python3 -m http.server {port}
  devsrv start ui --port auto -- npx vite --strictPort --port {port}
  devsrv start api --port 8080 --ready http:/health -- cargo run
  devsrv start worker --ready 'log:listening' -- node worker.js
  devsrv logs web -n 20;  devsrv stop web;  devsrv wait http://127.0.0.1:8080/
  devsrv wait http://127.0.0.1:8080/app.js --status 200      (until it is not 404)
  devsrv wait file build.log 'compiled|error';  devsrv wait cmd -- pg_isready -q

start runs CMD in the background (no shell; `-- sh -c '...'` for one) and returns when
it is ready. {port} in ARGS becomes the port, also given as $PORT (do not write $PORT
yourself: your shell would expand it first). --ready defaults to http with a port, else
none. A name runs once per git top level (or directory): a second start fails until stop.
The command keeps running after start returns; its stdout and stderr go to the log.

Output: the first line is the result. start prints only the address on stdout
(http://127.0.0.1:PORT/, or 127.0.0.1:PORT, or pid N); notes go to stderr. A failure
says what happened on the first line of stderr, then the log tail, then `hint:` lines
with the command to run next. --json (anywhere before CMD) prints one JSON object on stdout.

Exit status: 0 ok; 1 the condition did not hold (exited, not ready in time, already
started, unknown name, port in use, who: port free); 2 invalid input, or CMD cannot be
run; 3 devsrv could not work (state directory, broken record, the OS did not answer).

start: ready checks, ports and the supervisor
  http is ready on a status from 200 to 499; none means still running after 0.5s.
  --port auto picks a free port on 127.0.0.1. A fixed --port that is already in use
  fails with its owner. Before saying ready, devsrv checks that the port is held by the
  command's process group, not by someone else.
  Each start leaves one small supervisor process (devsrv __supervise) that records the
  exit status and does the stopping. When the command exits on its own, what is left of
  its group is stopped too, so do not background the server inside CMD
  (`sh -c 'server &'`). A single quoted CMD with spaces ("npm run dev") is run with sh -c.
  Everything from CMD on is the command's own: `start web -- npx vite --help` (or
  `start web npx vite --help`) gives --help to vite, not to devsrv.

stop: what it stops
  stop sends TERM to the command's process group, waits up to 5s, then KILL. A child
  that leaves the group (setsid, daemonizing) is not followed. Only process groups that
  devsrv started are stopped.

ls: what devsrv started
  One line per name: state, pid, port, age and the directory. ls shows this git top
  level (or directory); --all shows every one.

logs: the log of one name
  logs NAME prints the last -n lines (50). --follow-until REGEX waits for a line that
  matches, reading from the start of the current run's log, up to --timeout.

who: who listens on a port
  who PORT names the process that listens, and the devsrv name if devsrv started it.
  It never stops anything. Exit status 1 when the port is free.

wait: wait for a condition
  wait checks at once, then every 50ms (cmd: every 0.5s; --interval sets it), until the
  condition holds, and prints `ready after 1.2s: WHAT`. When --timeout (30s) passes, it
  fails (exit 1) with the last check on the first line.
  URL               a final HTTP status from 200 to 499, so 404 counts. --status takes
                    the codes that count instead: 200, 200-299, 2xx or 200,304.
  port N            a TCP connection is accepted (127.0.0.1, then ::1).
  file PATH         the file exists.
  file PATH REGEX   a line of the file matches (ANSI colors removed); the file may not
                    exist yet. The whole file is read each time, so a line left by an
                    earlier run counts too: write to a new file, or match what only this
                    run prints. On a timeout, the end of the file is shown.
  log NAME REGEX    a line of NAME's log, from the start of its current run; fails at
                    once when NAME has exited.
  gone PID          the process has exited.
  cmd -- CMD ARGS   CMD exits 0. Each run has no stdin and its own process group, which
                    is killed when the run ends, at the deadline, or when devsrv wait is
                    killed: nothing a run starts outlives it. On a timeout, the exit
                    status and output of the last run that finished are shown. All after
                    `--` is the command's, so put --timeout before `cmd`. One quoted line
                    with spaces runs with sh -c and may be followed by options:
                    wait cmd 'curl -sf URL | grep ok' --timeout 1m. A CMD that is not on
                    PATH fails at once (exit 2); a path (./bin/app) may appear later.
  It also takes --port N, --file PATH [REGEX], --log NAME REGEX, --gone PID, --cmd and a
  bare port. There is no `wait grep`: write wait file PATH REGEX.

compare: before and after, side by side
  Two starts with two names are two servers on two ports; no nohup or pid files. To
  compare a fix with the code before it, check the old code out in another worktree
  (a new worktree has no node_modules or build yet: install there first) and start both
  from the checkout with the fix:
    git worktree add ../app-before main
    devsrv start before --port auto -- \
      sh -c 'cd ../app-before && exec npm run dev -- --port {port}'
    devsrv start after --port auto -- npm run dev -- --port {port}
  Each start prints its URL; compare the two (curl, a browser, the tests against each),
  then devsrv stop before after. The same name can also run once in each worktree: a
  name belongs to its git top level, and each worktree is one. devsrv ls --all shows
  both; devsrv stop NAME stops the one of the directory it runs in.

state: where devsrv keeps its records
  State lives in $DEVSRV_STATE_DIR, else $XDG_STATE_HOME/devsrv, else
  ~/.local/state/devsrv. If it is not writable (a sandbox), start fails before running
  anything; set DEVSRV_STATE_DIR to a writable directory and keep it for later calls.

spelling: how options are written
  Options also take the form --opt=value. --timeout takes 30, 30s, 500ms or 2m.
